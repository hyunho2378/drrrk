# 드르륵칵 iOS 작업 규칙

드르륵칵 iOS 앱(SwiftUI)을 만들고 고칠 때 이 문서를 먼저 읽는다.

## 기준

- 화면 값의 기준은 팀 피그마 파일(네이버2팀_작업용, 페이지 "🟢 드르륵 1104")이다. 크기와 색, 글자, 반경, 간격은 피그마 Dev Mode 값을 그대로 쓴다.
- 인터랙션의 기준은 웹 프로토타입(`client/src/app`)에서 사용자와 맞춘 동작이다. 시간과 곡선은 웹 `tokens.js`의 motion 값을 그대로 옮긴다.
- 팀 피그마 원문 글자를 바꾸지 않는다. 바꿔야 하면 원문과 수정안, 이유를 먼저 보이고 허락을 받는다.

## 구조

- `DRRRK/App`: 앱 시작과 화면 흐름
- `DRRRK/DesignSystem`: 색, 글꼴(SUIT), 반경, 움직임 토큰. 화면 코드는 숫자 색을 직접 쓰지 않고 `DS` 이름만 쓴다.
- `DRRRK/Features/<화면 묶음>`: 화면 하나마다 `View`와 상태 `Model`(`@Observable`)을 나눈다.
- `DRRRK/Resources`: 피그마 원본 그림(해시 원본을 다시 압축하지 않음), 아이콘 SVG(벡터 유지), SUIT 글꼴

## Swift 규칙

- Swift API Design Guidelines를 따른다. 이름은 읽었을 때 뜻이 드러나게 쓴다.
- 최소 iOS 17, SwiftUI와 Observation(`@Observable`). 외부 라이브러리는 꼭 필요할 때만 Swift Package로 넣고 이유를 남긴다.
- 배치는 스택과 여백으로 짠다. 장면 그림 위에 얹는 요소(의자 이름표, 테이블)만 `SceneMap`으로 피그마 좌표를 옮긴다.
- 움직임은 `withAnimation`과 `matchedGeometryEffect`로 같은 화면 안에서 이어지게 하고, 화면 전체가 바뀌는 깜빡임을 만들지 않는다.
- 손에 오는 진동은 `UIImpactFeedbackGenerator`로 던지기와 마이크 같은 실제 행동에만 붙인다.
- 줄인 움직임 설정을 켠 사람에게는 움직임을 옅은 페이드로 바꾼다.
- 저장 전에 `swiftformat`으로 정리하고, `xcodebuild`로 빌드 오류 0을 확인한다.

## 화면 금지 규칙

- 이모지와 줄표, 가운뎃점을 화면 글자에 쓰지 않는다.
- 테두리와 탁한 색, 쓸데없는 장식을 넣지 않는다. 팀 다크 색만 쓴다.
- 나에게는 말하는 표시를 붙이지 않는다.

## 확인

- 시뮬레이터(iPhone 17)에서 띄워 피그마 화면과 나란히 놓고 본다.
- 보고에는 본 화면과 못 본 화면, 확인 방법을 적는다.
- git은 `dev` 브랜치에만 올린다. `main`과 배포는 사용자가 정할 때만 한다.
